# cfgm-identity-bootstrap

**역할**: identity 파일(`~/.claude-brain/memory-brain/identity/*.md`)이 비어 있으면, 짧은 대화로 사용자의 답을 끌어내 **Claude가 직접 초안을 작성**한다. 사용자 승인 후에만 파일을 쓴다. 원본 PAI의 "사람이 파일을 채운다" 철학을 "Claude가 인터뷰로 채운다"로 전환한다.

## 사용자 의도 해석

이 스킬은 슬래시 커맨드가 아니라 자연어 요청으로 호출된다. 아래 사용자 입력을 이 스킬의 분기로 매핑한다.

| 사용자 발화 | 동작 |
| --- | --- |
| "identity 인터뷰/부트스트랩 시작해줘", "텔로스 채워줘" 등 | 모든 파일 점검, 비어 있는 것만 인터뷰 |
| "telos만/persona만 (한) 파일만 채우자" | 해당 한 파일만 인터뷰 (telos · persona · user · tools · voice) |
| "refresh 모드로 보강해줘", "다시 물어봐줘" | 기존 내용을 유지하며 보강 질문 |

## 경로

- `~/.claude-brain/memory-brain/identity/telos.md`
- `~/.claude-brain/memory-brain/identity/persona.md`
- `~/.claude-brain/memory-brain/identity/user.md`
- `~/.claude-brain/memory-brain/identity/tools.md`
- `~/.claude-brain/memory-brain/identity/voice.md`
- `~/.claude-brain/memory-brain/identity/beliefs.md`
- `~/.claude-brain/memory-brain/identity/models.md`
- `~/.claude-brain/memory-brain/identity/strategies.md`
- `~/.claude-brain/memory-brain/identity/ideas.md`

goals는 이 스킬이 아니라 `/cfgm-identity` + CLI(`bin/cfgm-identity-goal.ts`)로 관리한다.

PAI 원본 10개 TELOS 파일 대비 매핑:
- MISSION → `telos.md`
- GOALS → 별도 `goals/` (CLI 관리)
- PROJECTS / CHALLENGES → `Problem` 엔티티 + FlowGraph (별도 파일 없음)
- LEARNED / NARRATIVES → FlowGraph 블록 (`flow-delta.jsonl`)
- BELIEFS → `beliefs.md`
- MODELS → `models.md`
- STRATEGIES → `strategies.md`
- IDEAS → `ideas.md`

## 절차 (각 파일마다 반복)

### 1. 파일 읽기
`Read` 도구로 대상 파일 전문을 읽는다.

### 2. 비어 있음 판정
다음 변환 후 결과가 비면 "비어 있음":
1. `<!-- ... -->` HTML 주석 제거
2. `#`, `##` 등 제목 줄 제거
3. 공백·개행 제거

비어 있지 않고 `refresh` 모드가 아니면 **건드리지 말고** 다음 파일로.

### 3. 인터뷰
아래 파일별 질문 세트를 **한 번에 1~2개씩** 묻는다. 사용자 답변을 기다렸다 다음 질문. 사용자가 "패스"·"모름"·"다음"이라고 하면 해당 질문은 **빈 채로 두고** 다음으로 넘어간다.

### 4. 초안 작성
받은 답변만으로 파일 본문을 작성. 규칙:
- **1인칭** ("나는 …"). AI 입장에서 쓰지 않는다.
- **과장·추정 금지**. 사용자가 말하지 않은 것은 쓰지 않는다.
- **파일당 1~3KB 이내**. CLAUDE.md 시스템 프롬프트에 매 턴 포함되므로 간결해야 한다.
- 헤딩 구조는 기존 템플릿을 따르되, 사용자가 답하지 않은 섹션은 빈 상태 또는 제거.

### 5. 승인
초안 전문을 사용자에게 보여주고 질문한다: **"이 내용으로 저장할까요? (y/n/edit)"**
- `y` → 6단계
- `n` → 초안 폐기, 다음 파일로
- `edit` 또는 수정 요청 → 지시대로 다시 작성 후 5단계 반복

### 6. 커밋
`Write` 도구로 해당 파일에 덮어쓰기. 완료 메시지 1줄로 보고.

### 7. 다음 파일
순서: **telos → persona → user → tools → voice → beliefs → models → strategies → ideas**. 모든 파일 처리 후 `/cfgm-identity show`로 총 크기 요약 권장.

## 파일별 질문 세트

### telos.md — 존재 목적
- 어떤 순간에 가장 "내가 살아있다"고 느끼나요?
- 지금 하고 있는 일 중에 5년 뒤에도 여전히 하고 있을 것 같은 건?
- 타협하지 않을 원칙 하나만 꼽는다면? (2~3개 더 있으면 좋음)
- (옵션) 20년 뒤 누군가 당신을 한 문장으로 요약한다면 뭐였으면 좋겠어요?

초안 구조:
```markdown
# TELOS

## 나는 무엇을 위해 깨어나는가
{응답 1 기반 1~2문장}

## 5년 뒤 나
{응답 2 기반 1~2문장}

## 타협 불가능한 원칙
1. {응답 3-1}
2. {응답 3-2}
3. {응답 3-3}
```

### persona.md — AI 성격
- AI가 당신과 얘기할 때 **어떤 톤**이 편한가요? (예: 간결·직설 / 부드럽게 돌려서 / 학술적 정확 / 친구 같은)
- 의견 차이가 있을 때 AI가 어떻게 반응하길 원하나요? (맞장구 / 반대 제시 / 근거 요구)
- 가장 싫어하는 AI 행동 하나만 꼽는다면?

초안 구조:
```markdown
# Persona

## 기본 톤
{응답 1}

## 의사결정 스타일
{응답 2}

## 피해야 할 태도
{응답 3}
```

### user.md — 사용자 프로필
- 지금의 직업/역할을 한 줄로?
- 주된 기술 스택이나 도메인은?
- 지금 가장 많은 시간을 쓰고 있는 문제/프로젝트는?
- (옵션) 중요한 맥락이나 제약 (예: 팀·조직·지역)

초안 구조:
```markdown
# User

## 역할
{응답 1}

## 전문 분야
{응답 2}

## 현재 집중 영역
{응답 3}

## 맥락
{응답 4 또는 생략}
```

### tools.md — 도구와 환경
- 주력 OS / 쉘?
- 주력 언어·런타임은?
- 주로 쓰는 에디터/IDE?
- 빼놓을 수 없는 CLI/SaaS 하나만?

초안 구조:
```markdown
# Tools

## OS / Shell
{응답 1}

## 언어 / 런타임
{응답 2}

## 에디터
{응답 3}

## 주요 CLI / SaaS
{응답 4}
```

### voice.md — 응답 스타일
- 기본 응답 길이는 짧은 쪽인가요, 긴 쪽인가요?
- 코드블록·불릿을 선호하는 정도? (항상 / 필요할 때만 / 최소화)
- 한국어/영어 섞는 스타일? (한국어 기본·용어만 영어 / 자유롭게 혼용 / 영어 우세)
- 피하고 싶은 표현/어투 있나요? (예: "저"·"제가"·과도한 공손)

초안 구조:
```markdown
# Voice

## 길이 기본값
{응답 1}

## 포맷 선호
{응답 2}

## 언어
{응답 3}

## 피해야 할 표현
{응답 4 또는 생략}
```

### beliefs.md — 신념과 원칙
- 지금 의사결정에서 가장 자주 기준이 되는 원칙 하나를 꼽는다면?
- 사회 통념과 달라도 지키고 있는 믿음이 있나요?
- 어떤 선까지는 타협하지 않겠다고 스스로 정해놓은 게 있나요?
- (옵션) 최근 흔들린 믿음이 있나요?

초안 구조:
```markdown
# Beliefs

## 핵심 가치
{응답 1}

## 사회 통념과 다른 믿음
{응답 2 또는 생략}

## 타협 불가능한 선
{응답 3}

## 최근 흔들린 믿음
{응답 4 또는 생략}
```

### models.md — 멘탈 모델
- 복잡한 문제를 분해할 때 가장 자주 꺼내는 프레임워크/법칙이 있나요?
- 다른 사람에게 "이렇게 생각해보라"고 자주 권하는 비유가 있나요?
- 경험에서 얻은 "거의 항상 맞는" 법칙 하나만 꼽는다면?

초안 구조:
```markdown
# Models

## 즐겨 쓰는 프레임워크
{응답 1}

## 유용한 비유
{응답 2 또는 생략}

## 경험적 법칙
{응답 3}
```

### strategies.md — 반복 사용하는 접근법
- 새 프로젝트를 시작할 때 첫 수로 무엇을 하나요?
- 작업이 막혔을 때 거의 항상 시도하는 탈출구는?
- 큰 결정 앞에서 사용하는 판단 기준이 있다면?

초안 구조:
```markdown
# Strategies

## 새 프로젝트 시작 시
{응답 1}

## 막혔을 때
{응답 2}

## 큰 결정 앞에서
{응답 3 또는 생략}
```

### ideas.md — 진행 중인 아이디어
- 지금 머릿속에서 잘 안 떨어지는 주제가 있나요?
- 시간만 나면 해보고 싶은 것 하나?
- 해결되면 좋겠다고 생각하는 문제 하나?

초안 구조:
```markdown
# Ideas

## 최근 꽂힌 주제
{응답 1 또는 생략}

## 언젠가 해보고 싶은 것
{응답 2}

## 해결하고 싶은 문제
{응답 3}
```

## 금기

- **승인 없이 파일을 쓰지 않는다.** 초안 미리보기와 y/n 확인 필수.
- **사용자가 말하지 않은 것을 넣지 않는다.** "보통 이런 답이 많아서…"는 금지.
- **민감/타인 정보 유도 질문 금지.** telos에서 가족·친구 이름 같은 것 캐지 말 것.
- **한 번에 모든 파일을 연속으로 강요하지 않는다.** 사용자가 "여기까지 하자"고 하면 즉시 멈추고 현재까지의 승인분만 커밋.
- **refresh 모드가 아니면** 이미 채워진 파일은 건드리지 않는다.

## 완료 후 제안

다섯 파일 모두 처리했다면:
1. `bun run bin/cfgm-identity-goal.ts show` — 총 크기 확인 (20KB 초과 시 경고).
2. `/memory` 실행을 권장 — 사용자가 CLAUDE.md에서 @import 목록을 직접 볼 수 있다.
3. 장기 목표가 있다면 `/cfgm-identity`의 goal CLI 안내.
