## 0. 개요

본 RFC는 Epic 0~6 (434 tests pass, Epic 12a 완료 시 439)로 완성된 **수신·보존·구조화·검증·아카이브** 계층 위에 다음 5개 진화 축을 얹어 CFGM-OS를 **"PAI 정체성 기반 자가성장 메모리 엔진 v2"** 로 격상시키는 설계 문서다. (이전 수치 411은 Epic 5 시점 베이스라인; 최신은 `bun test` 결과.)

1. **스킬 없이 KG 암묵 호출** — Flow Graph + micro-ontology가 절차 지식으로 작동
2. **Gap Question Engine 능동성** — 타이밍·번들·우선순위·답변 학습 루프
3. **개인 → 거대 온톨로지 export** — 익명화·staging·user confirm 경로
4. **PAI 자가성장** — 관찰 → 패턴 증류 → 스킬/훅/flow-pattern 자동 초안 + 사용자 승인
5. **OMX/OMC 수준 배포 DX** — `/cfgm-doctor`, `/cfgm-setup`, `/cfgm-hud`, 엣지케이스 복구

구현 금지. 합의된 설계만. 모든 결정은 이번 RFC에서 닫는다.

## 2. 데이터 모델 변경 (섹션 핵심)

### 2.1 FlowBlock schema diff (BC-2, BC-7)

```diff
 export type FlowBlock = {
-  supersededBy: string | null;
+  supersededBy:
+    | { kind: "block"; blockId: string }
+    | { kind: "sentinel"; reason: string }  // 거버넌스 발행 supersede
+    | null;
+  embeddingId?: string;           // SemanticIndex 참조 (Epic 11)
+  lastQueriedAt?: string;         // attention/recency 신호
+  synthesizedFrom?: string[];     // Skill 블록 전용 — source ontologyModuleIds
+  executionTrace?: { stepId: string; outcome: "ok"|"skipped"|"fail" }[];
+  identityRef?: { kind: "telos"|"persona"|"user"|"tools"|"voice"|"goal"; key: string };
 };
```

- 신규 BlockType 3종: `Skill`, `Identity`, `Trace` (`src/core/flow/types.ts:1-6` union 확장)
- 신규 RelationKind 3종: `synthesizes`, `embodies`, `satisfies`
- v1 reader는 unknown type/op를 if-continue로 방어 → **Backward-compat 자동**

### 2.2 신규 FlowDelta op 4종

### 2.4 ResumeSheet v2 (BC-1) — **opt-in, default off**

ADR-004 단일 세션 가정 유지. `config.ts.MULTI_SESSION_MODE`(기본 false)가 true일 때만 v2 멀티세션 필드 활성화. v1 sheet는 v2 default로 promote 후 consume.

## 6. PAI v2 — 5층 아키텍처 (T3 수용)

```
L5 Synthesizer   : skill.md / hook.ts / flow-pattern.yaml 초안
L4 Distiller     : 후보 탐지(작업/도구/스타일/휴리스틱)
L3 Behavior Ledger: 관찰 이벤트 append-only (identity-observations/)
L2 Identity Core : telos/persona/user/tools/voice (v1.5 유지)
L1 Identity Axioms: telos 타협 불가능 원칙 (immutable, drift-lock)
```

### 6.1 학습 대상 × 신호 × 임계값 (동결)

| 학습 대상 | 소스 이벤트 | 추출 신호 | 증거 임계 | 반영 대상 |
|---|---|---|---|---|
| 작업 패턴 | post-tool-use Write/Edit/Bash seq + activeProblem.templateId | n-gram(3~5) 빈도 | ≥7 problems, confidence≥0.7 | flow-pattern.yaml 후보 |
| 도구 선호 | pre-tool-use 도구 선택 + 거부/승인 | 호출 빈도·거부율 | ≥30 호출 + 유의 편차 | tools.md 델타 |
| 응답 스타일 | user-prompt-submit + 응답 길이·포맷 + 교정 | 평균 길이, 코드블록 비율 | 최근 50턴 p<0.05 | voice.md 델타 |
| 의사결정 휴리스틱 | gap 답변 + 채택/기각 | 선택 지연, 선호 클래스 | 5 의사결정, 일관 패턴 | persona.md + skill.md 후보 |

### 6.2 4중 게이트 (G1~G4)

| 게이트 | 조건 | 아티팩트 |
|---|---|---|
| G1 Evidence | evidenceCount<N 또는 confidence<τ (skill N=3/τ=0.7, hook N=5/τ=0.85, flow N=3 resolvedRuns) | `candidates/<id>.json` rejected |
| G2 Sandbox | shadow 자동 생성 → dry-run → no-op 자동 기각 | `shadow-runs/<id>-<ts>.log` |
| G3 사용자 승인 | canary 진입 전 명시 y/n/edit, 48h 무응답 자동 폐기 | `approvals/<id>.json` |
| G4 Canary + Rollback | N=3 problem canary, override/rollback 1회 발생 시 quarantine | `canary/<id>.jsonl` |

### 6.3 충돌 해결 (C1~C4)

| 충돌 | 탐지 | 해결 |
|---|---|---|
| C1 identity vs synth | voice.md 키워드 ↔ synth description 반대 | synth 측 기각 |
| C2 multi-profile | $CFGM_PROFILE 스택 로딩 시 중복 감지 | project>user>team + 경고 |
| C3 cross-harness | `identity.lock` + mtime | lock 미획득 시 drafts/에만 |
| C4 self-generated vs user-edited | snapshot sha256 비교 | 자동 머지 금지, 재인터뷰 요구 |

### 6.4 측정 기준

- M1: 14일 내 ≥1 자동 합성 산출물이 G1~G4 통과
- M2: 합성 산출물 사용자 수동 편집률 <50%
- M3: Identity 총 크기 ≤20KB
- M4: L1 drift-lock 위반 시도 기록되되 반영 0건
- M5: Rollback ≤5초

### 6.5 **Critic 주문 수용**: 자동 합성 → **Skill Suggestion**

Hermes의 closed loop는 품질 이슈 누적 위험. 본 설계에서 "auto-activate"는 하지 않고 **G3 사용자 승인 후 canary** 에서만 활성화. 차별점은 **"인과 chain → skill frontmatter 기계번역 규칙"** (§10 청구항 참조).

## 7. Gap Engine v2 (진화축 #2 해결)

### 7.1 VoiLearner — 답변 학습 루프

- Thompson sampling per-detector posterior (Beta(α,β))
- outcome="answered-quality" → α+=1; "ignored"/"rejected" → β+=1
- 최종 score = `0.5 * baseline + 0.5 * learned` (급격한 drift 방지)
- epsilon-greedy 5% exploration (R1 다양성 보호)
- **default-off 경로 byte-equal** (D4) — opt-in flag로 활성화

### 7.2 QuestionBundler — 번들 + 예산
- `budget.maxQuestions=1`로 호출 시 v1 `injectQuestion()`과 동치
- 같은 subjectBlockId/detectorId 질문 최대 3개까지 묶음
- rationale 포함하여 사용자에게 묶인 이유 설명

### 7.3 FatigueModel — 타이밍
- 연속 3회 무시 → cooldown 30분
- session 당 budget 기본 5
- **디버깅 모드** 감지(Bash exit≠0 연속 3턴) → budget ×2

### 7.4 AnswerQualityScorer
3조건 검사(§T2 5.4) → `voi-feedback` ledger append → VoiLearner 학습
